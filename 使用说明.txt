Windows 模型选择器排查包
2026-11-18

这是排查工具和一次实际经历，不是 OpenAI 官方软件，也不是一键修复器。
无需 Dot，也不需要额外付费 API 或管理员权限。

包里有什么
文章-可直接发布.txt：按起因、经过、结果写的推送正文。
assets/cover.png：带“6.2去哪了？”标题的概念封面。
Inspect-ModelCatalog.ps1：默认离线，只读取两份模型缓存并输出摘要。
Refresh-ModelCatalog.ps1：可选，显式确认后运行应用自带的目录诊断。
tests/：用于验证读取逻辑的虚构测试数据，不含真实账号资料。

先做三个对照
确认查看的是新建 Work 的模型菜单。
用同账号网页版对照；确认网页有、桌面没有。
检查桌面更新；如果要重启，先保存并结束不能中断的工作。
本次用户重启应用和电脑后没有立即恢复，无需反复重启。

运行检查
先解压 ZIP。开始菜单搜索 Windows PowerShell，打开一个普通窗口。
输入 cd 后加解压后的文件夹路径，例如：
cd "$HOME\Downloads\gpt62-picker-kit"

然后运行：
.\Inspect-ModelCatalog.ps1

如果系统提示禁止运行脚本，不需要关闭系统安全设置或照着网上教程永久修改执行策略。你可以用记事本打开脚本，阅读后把内容复制到同一个 PowerShell 窗口执行；若单位设备的策略阻止这类操作，请遵守管理员要求。也可以只阅读文章，暂用网页版。

脚本默认按当前终端的 CODEX_HOME 查找目录，没设置时使用 $HOME\.codex。
它只读 models_cache.codex_work_desktop.json 和 models_cache.json，不读取登录文件、密钥或聊天记录。
如果你明确知道桌面用了别的配置目录，可传入：
.\Inspect-ModelCatalog.ps1 -CodexHome 'D:\你的Codex目录'
不要猜路径或全盘扫描。当前终端环境也未必等同正在运行的桌面应用环境。

怎么看结果
ok：文件成功读取。查看 Models 中的模型名和 Visibility。
没有匹配条目：这份目录里没有以 gpt-6.2 开头的条目。
list：目录把该模型标记为可列出；实际界面还可能有其他过滤条件。
missing：该文件未找到；不同版本、安装方式或配置目录可能不同。
unknown-format：文件结构与本脚本支持的格式不符。
read-or-parse-error：读取或解析失败。脚本不会把原文件作为报错全文输出。
too-large：文件超过20 MiB，本工具不继续读取。
脚本遇到单个异常文件会继续检查另一份，不需要重新打开终端。

可选的目录诊断
只有打算请求刷新目录时才运行：
.\Refresh-ModelCatalog.ps1 -RunRefresh

这一步会寻找当前账户安装的 OpenAI.Codex Windows 应用包，并调用其中 appesources\codex.exe 的 debug models 命令。找不到唯一安装包或文件会停止，不安装软件、不尝试其他可执行文件。
该命令可能联网并更新模型缓存；不发起模型推理。它不手动改配置、不删除或覆盖缓存，也不重启应用。
等待命令结束；长时间无响应时按 Ctrl+C 停止本次诊断，不连续打开新窗口。输出被抑制，以免几十万字元数据刷屏。
退出码0表示诊断进程成功结束，不表示桌面菜单已修复。随后再运行检查脚本，回到桌面新建 Work 验证。
不加 -RunRefresh 时只打印说明，不运行诊断。

本次实际结果
普通缓存里有 gpt-6.2-sol、gpt-6.2-astra，visibility 均为 list。
桌面专用缓存当时没有这两个条目，两份记录版本都是0.169.0。
后来桌面模型菜单恢复。期间做过诊断和工作区测试，没有手动复制、删除或改写缓存，触发恢复的具体步骤尚未定位。
UTF-8 解决的是 PowerShell 读取诊断数据的问题，不是桌面修复开关。
